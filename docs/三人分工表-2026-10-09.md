## 二、各线验收命令（live，MiMo-V2.6-Flash）

模板：`.\.venv\Scripts\python.exe scripts\run_agent_eval.py --files <集名> --mode live --model MiMo-V2.6-Flash --concurrency 2 --out tmp/<输出>.json`（`--files` 相对 `eval/agent/` 解析；多集逐个跑）

- B 线：`eval_special_multitable`、`eval_basic_nl2sql`；关联 `eval_special_formula`、`eval_cross_source`、`eval_special_multimodal`
- C 线：`eval_special_clarification`、`eval_special_negative`、`eval_multiturn`；关联 `eval_cross_source`、`eval_special_multitable`
- 每日全量回归：`--all`，输出 `tmp/eval-daily-<日期>.json`

## 三、冻结契约（三线改动前先对齐，改契约需三线确认）

1. **澄清槽位词表**＝金标准命名（period、comparison_period、data_scope、target_metric、media_scope、genre_scope、year、scope）；C 线维护，A/B 不得自造槽位名。
2. **状态枚举语义**：answered / clarification_required / insufficient_evidence / unsupported / error 的判定边界表，C 线出稿、三线签认。
3. **证据引用格式**：source_refs（文档编号＋段落/单元格）绑定结构，A 线为格式 owner；B 的计算结果、C 的答案文本按此格式填充。
4. **时间粒度契约**：整年/季度/月的解析输入输出由 B 线实现；A 的检索加权与 C 的澄清触发复用同一解析结果，不各自解析。
5. **路由信号表**：排名/分布/Top-N/实际vs目标/查数外形等信号→sql 或 cross_source 的映射由 C 线维护，B 线提供 SQL 能力边界说明。
