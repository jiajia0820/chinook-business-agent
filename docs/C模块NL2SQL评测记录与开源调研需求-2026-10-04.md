## 1. 目的与范围

记录当前 C 模块真实模型问数的首次本批次结果，供团队验收和开源方案调研使用。本文记录事实和待验证的改进方向，不代表新增开发已完成，也不代表已经选定开源项目。

C 负责 SQL 全链路：数据适配、Schema、表字段和实体匹配、自然语言生成 SQL、安全校验、只读执行、错误处理与结构化返回。A 提供业务口径及标准答案；B 负责 Agent 路由、文档检索、页面与整体编排。主要开发语言为 Python，计划使用 Chinook 与 AdventureWorks；本批次仅验证本地 Chinook SQLite。

当前链路：自然语言问题 → 授权 Schema 和目录上下文 → 模型生成 sql/params JSON → 程序校验 → 只读执行 → 返回 SQL、结果和来源。已有数据库接入、安全执行能力应尽量保留。

### basic-nl2sql-009

题集标准：按 MediaTypeId 分列销售额和销量；音频类型与视频类型分别展示。

## 5. 已证明的能力与尚未证明的能力

## 7. 开源代码调研要求

选型目标：为 C 的 Python SQL 全链路补充成熟实现或设计，而非替换同伴的页面、RAG 和整体 Agent。优先调查一个可独立调用的 SQL 引擎/后端项目，避免同时拼装多个完整平台。

### 必查项目能力

1. Schema Linking 是否真的包含相关表字段选择、实体值匹配、外键路径补全，而非仅将全部 DDL 放入提示词。
2. 业务口径如何配置：能否表示音频集合、成交单价、订单去重、账单国家，以及对应来源和版本；新数据库能否用配置接入。
3. 是否提供完整 NL → SQL → 校验 → 执行 → 结果链路；内部 SQL 子流程可由 C 管理，外层产品 Agent 仍由 B 负责。
4. SQL 生成是否支持当前模型 API；是否强绑云服务；API 模型与本地模型是否可替换。
5. 错误处理是否区分语法、语义、服务超时、权限和输出格式；重试上限、预算和每次重新校验是否明确。
