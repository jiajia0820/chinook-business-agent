## 本阶段：数据库查询初版与统一接口适配

状态：已完成本阶段实现；当前为限定句式规则基线，尚未接入大模型。

| 已完成内容 | 当前能力 |
| --- | --- |
| Chinook 数据库接入 | 读取表、字段、主外键、记录数量和订单日期范围 |
| 基础问数 | 客户、订单、曲目等数量查询，以及音乐类型列表 |
| 经营指标查询 | 按支持句式查询年度、季度、音乐品类的销售额、销量、订单数 |
| 排名查询 | 按支持句式查询国家、音乐类型、艺术家的销售额前 N 名 |
| 指标口径 | 销售额采用成交明细单价乘数量求和；明确音乐或品类范围时筛选音频；一般销售查询标明全部媒体范围 |
| 只读 SQL 工具 | 参数绑定、只读连接、授权器、单语句限制、超时、行数限制、结构化错误 |
| 团队接口适配 | `query` 接收统一 SQL 工具请求，返回对象数组；支持 Python 和本地 HTTP 调用 |
| 演示与证据 | 提供问答演示入口，返回 SQL、结果、来源表、统计口径和实际工具执行记录 |
| 异常反馈 | 对部分缺条件问题、无数据、需要文档和不支持的问法返回相应状态 |

实现说明见 [C 模块接口说明](c-module.md)，正式代码位于 `backend/chinook_c.py`。原 `C模块初版/chinook_c.py` 为兼容启动入口；原目录中的旧测试和示例不作为当前统一接口的验收依据。

### 当前限制

- 自然语言入口依赖固定句式；尚无国产模型 API 调用、自由问法或业务黑话理解能力。
- 当前 SQL 工具输入为 SQL，尚无完整的“结构化查询计划 → 校验 → SQL”入口。
- 可以读取 Schema，但还没有独立、完整的候选表字段匹配和业务语义映射模块。
- 增长率、同比、环比尚未计算；相关问题目前只返回澄清提示。
- `session_id` 仅透传，尚无多轮记忆；目标问题只提示需要文档，未完成跨源判断。
- 问答 HTTP 入口用于 C 独立演示；完整网页、Agent、会话、角色权限和 RAG 由 B 负责。
- 证据参数等数组元素的细节仍需 A、B 对齐；不能将现有返回字段齐全等同于全部业务能力完成。

## 下一阶段：查询计划驱动的 C 模块与国产模型联调

状态：待开发。目标是让用户的不同表达经国产模型理解后，转换为统一查询计划，由 C 可靠查询数据库。依据用户明确要求，模型选型须符合比赛国产大模型要求；具体厂商、型号及平台限制仍需对照赛题确认。

建议流程：网页 → B 的 Agent 调用国产模型 API → 查询计划 → C 校验、生成 SQL、只读执行 → Agent 组织有依据的答案 → 网页。模型由 B 统一调用是当前建议，须由团队确认；C 本身不必重复接入模型 API。

### 任务清单

- [ ] A、B、C 对齐查询计划调用方式：以现有 `interface-contract.md` 第三节为基础，明确入口、输入输出、缺失条件及错误处理；接口变更由 A 维护，不能把提案当作已确认契约。
- [ ] C 完善数据库语义字典：字段含义、实体别名、指标计算和关联路径；由 A 确认业务术语，含糊黑话不能擅自定义。
- [ ] C 实现查询计划校验：核对指标、实体、时间、范围及支持条件；缺条件时报告缺口，不静默忽略无法映射的条件。
- [ ] C 实现查询计划到参数化 SQL 的转换：支持时间、品类、国家、分组、排名的约定组合；保留现有 SQL 工具接口。
- [ ] C 补充业务正确性测试：音乐与全部媒体范围、关联重复计数、订单去重、时间边界、无数据与不支持条件。
- [ ] A 提供或复核标准答案，C 建立口语、别名、多条件及歧义问题的测试记录；尚未取得的准确率不得填入报告。
- [ ] B 确认国产模型并接入 API，提供查询计划；B、C 完成真实模型调用和网页联调，记录模型配置、输入、计划、结果及失败原因。

前五项中的 C 实现可以先按契约草案推进，不依赖模型密钥；正式接口以团队确认为准。模拟计划测试通过只代表 C 独立验证通过，不能称为真实模型或网页联调完成。

### 阶段验收标准

| 场景 | 预期行为 |
| --- | --- |
| “2025年Rock销售额是多少？”与“25年摇滚卖了多少钱？” | 真实模型理解后产生等价条件，C 返回相同正确结果 |
| “2025年美国的摇滚音乐销售额是多少？” | 同时应用年份、账单国家、Rock 品类和音频范围；国家口径由 A 确认 |
| “摇滚流水怎么样？” | 缺时间或术语存在歧义时明确追问，不猜测指标或静默省略条件 |
| 不存在的字段、不支持的指标或非法计划 | 返回明确错误或能力限制，不执行未经校验的查询 |
| 正常查询与无数据查询 | 返回真实结果、SQL、口径、来源和执行记录；无记录不擅自解释为真实业务为零 |
| 接入团队网页 | 从提问到真实模型、C 工具及页面展示完整跑通，保存可复现记录 |

增长率计算、经营目标文档联合判断以及更复杂多轮能力作为后续扩展，不在本阶段默认宣称完成；如需调整范围，由团队明确后更新本文。

## 协作与交付约束

- A 负责口径、术语、标准答案及统一接口；B 负责模型调用、Agent、会话、网页和文档检索；C 负责数据库映射、SQL 生成、校验和执行。
- 模型密钥使用后端环境变量或不入库的本地配置，禁止写入网页、源码或提交到仓库。
- 阶段完成后先汇报改动、验证结果、剩余限制和拟推送分支；只有用户明确同意本次成果后才推送 `zx`，不自动推送或合入 `main`。
