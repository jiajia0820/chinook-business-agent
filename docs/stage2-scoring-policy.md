# 阶段二评分政策 v1

评分器 `scripts/eval_scoring.py`，版本 `stage2-policy-1`。以下政策在业务修复前确定；正式题库、金标准和分母不修改。评分器后续若发现缺陷，必须记录原因、版本和历史重评分，不把分数变化计为模型提升。

- `status`、必填非空字段、结构化错误与澄清是硬约束。路由差异单列接口诊断；业务结果、必需来源和行为全部满足时，可接受等价执行路径。应有 SQL 的题仍检查完整 SQL 结果。
- 无排名要求的行按多重集合比较，重复记录不丢失。排名检查指标顺序；同值名次允许互换，但不能返回金标准集合之外的对象。不会忽略缺行、缺列或错误身份字段。
- 金额/舍入结果绝对容差 0.01；计数与实体编号精确。百分比须带 `%`，可有空格，不把金额或 0.9405 比率当作 94.05%。公式字符串检查等号右侧，递归检查复合月度结果及周期绑定。
- 只在答案和结构化计算中检查计算产物；文档编号、日期和实体编号不能充当业务数值。公式题必须返回结构化计算。文档题须回答必要事实、材料、规则和日期，检索到文档编号不能替代完整答案。
- `gold_answer_requirements` 的人工可读语义落实为评分器内的显式、可审查概念断言及金标准事实比较。这些是评测专用，不传入运行时系统或模型。来源断言检查指定文档、页码和图片区域定位；文本事实同时检查答案。
- 澄清槽位有明确名称时严格比较。多轮的泛化 `required_context` 允许具体必要槽位；合法澄清不判失败。多轮逐轮执行相同政策，不把日期或编号拆成业务指标。
- 一轮 80 个评分单位保持固定，API 失败仍在分母中。历史重评分独立标注，live 正式运行并发默认 1；完整证据使用独立目录。

运行：`python scripts/stage2_eval.py --rescore-history` 或 `python scripts/stage2_eval.py --all --mode live --concurrency 1`。每次自动创建 `tmp/stage2-eval/<run-id>/`，记录元数据、完整响应、模型尝试与降级、失败和对比说明；不记录请求密钥或整份模型提示词。

## v1.1 修正说明

检查完整 OCR 响应发现 `2025.10.20` 与中文日期等价；海报在活动日期印年份，截止时间只印月日，应检查同一答案的年份与完整月日。修复日期转换及日期数字误当业务数值的问题，接受原文明确的“两个目录条目”“另有”“延伸栏目”语义同义表达。日期、来源、材料完整性要求不降低；旧历史响应另行重评分，分数变化不归为系统提升。

## v1.2 修正说明

审查跨源完整响应发现两类评分缺陷：有 `expected_tables` 的题可能仅引用文档而没有 SQL 事实；`cross-009` 的 `gold_calculation` 是月度来源审计对象，未要求执行算术，却被强制要求返回计算对象。现在要求这些题实际返回 SQL 来源；只有含 rate/gap/growth_rate/result/formula/sum/average_order_value 算术键的金标准才强制 calculations，月度审计仍严格检查每个月与金额的绑定、来源和冲突解释。此修改独立版本化，并重评分历史响应；不归为业务能力提升。

## v1.3 修正说明

金标准将客单价的计算键命名为 `aov`，v1.2 算术键列表遗漏该等价名称。补入后客单价题同样必须有结构化 calculations，禁止只报一个文本数字。历史响应重评分独立保存；v1.2 完整模型响应中该题已有计算证据，业务成绩不因本次政策修正提升。

## v1.4 第二次修改的完整业务断言

依据原指令第20.2、20.4节收紧两条跨源流程验收，不修改原80单位题库、题意或分母。`cross-004` 原有12位Rock购买客户及Rock金额/订单中间结果继续完整比较；新增独立查询核实的每客户全部音频金额、A层最终名单、阈值及USD单位、季度与本轮SQL单元格引用检查。独立核实采用先取去重购买人群、再逐客户查询全部音频的两步方法，证据冻结于 `scripts/stage2_cross_assertions.json`（评测专用，运行时禁止导入）。阈值依据D04原表P15，计算口径P11，适用期P113；不从原gold的Rock金额推算全部音频金额。

`cross-006` 原有候选商品/金额结果比较继续保留，增加逐商品成交状态、金额单位、SQL事实与D05候选/D11条件引用、2025Q3期间及图片定位检查。新版评分不允许只有中间数值或原文出现名单就通过。旧S2-005完整响应按v1.4独立重评分以复核8/10基线；报告评分变化与系统变化分开。新增工程测试不进入正式分母。


## v1.5 第三次修改：基础集15题与严格新增断言

用户明确授权新增基础011–015；当前正式85单位（80单轮、5会话）、95请求，历史80单位成绩不改写。原001–010及其他专项评分逻辑保留。独立核对发现v1.4的无序结果比较会接受月份乱序、并列客户ID倒序；金额0.01容差也会接受零值变0.01。仅对新增五题按gold逐行比较、金额允许最多0.000001的浮点表示误差（不允许不同分金额），计数与ID严格比较。新增响应字段/route、期间、未截断及商品编号不作为年份的断言。正反例测试覆盖错序、缺行、NULL/错误零、错ID、错计数、错期间和截断；这属于收紧验证，不是提高成绩的放宽。

直接run_agent_eval.py的live入口复用现有完整证据包装，串行绑定请求与模型调用，保存原始候选与接受SQL；累计一次外部API失败后暂缓后续尝试，避免反复碰运气。最终报告保留business_passed作诊断，但pending_external_api题passed=false，保留在15题分母。现有stage2_eval.py历史入口默认评分行为保留；本次专项使用用户给定的直接命令。
