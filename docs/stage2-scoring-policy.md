# 阶段二评分政策 v1

评分器 `scripts/eval_scoring.py`，版本 `stage2-policy-1`。以下政策在业务修复前确定；正式题库、金标准和分母不修改。评分器后续若发现缺陷，必须记录原因、版本和历史重评分，不把分数变化计为模型提升。

- `status`、必填非空字段、结构化错误与澄清是硬约束。路由差异单列接口诊断；业务结果、必需来源和行为全部满足时，可接受等价执行路径。应有 SQL 的题仍检查完整 SQL 结果。
- 无排名要求的行按多重集合比较，重复记录不丢失。排名检查指标顺序；同值名次允许互换，但不能返回金标准集合之外的对象。不会忽略缺行、缺列或错误身份字段。
- 金额/舍入结果绝对容差 0.01；计数与实体编号精确。百分比须带 `%`，可有空格，不把金额或 0.9405 比率当作 94.05%。公式字符串检查等号右侧，递归检查复合月度结果及周期绑定。
- 只在答案和结构化计算中检查计算产物；文档编号、日期和实体编号不能充当业务数值。公式题必须返回结构化计算。文档题须回答必要事实、材料、规则和日期，检索到文档编号不能替代完整答案。
- `gold_answer_requirements` 的人工可读语义落实为评分器内的显式、可审查概念断言及金标准事实比较。这些是评测专用，不传入运行时系统或模型。来源断言检查指定文档、页码和图片区域定位；文本事实同时检查答案。
- 澄清槽位有明确名称时严格比较。多轮的泛化 `required_context` 允许具体必要槽位；合法澄清不判失败。多轮逐轮执行相同政策，不把日期或编号拆成业务指标。
- 一轮 80 个评分单位保持固定，API 失败仍在分母中。历史重评分独立标注，live 正式运行并发默认 1；完整证据使用独立目录。

运行：`python scripts/stage2_eval.py --rescore-history` 或 `python scripts/stage2_eval.py --all --mode live --concurrency 1`。每次自动创建 `tmp/stage2-eval/<run-id>/`，记录元数据、完整响应、模型尝试与降级、失败和对比说明；不记录请求密钥或整份模型提示词。
