## 1 数据接入与 Schema

文件：`backend/sql_module/{profiles,schema,errors}.py`、`adapters/{sqlite,postgresql}.py`、`__main__.py`、`profiles/chinook/profile.json`、AdventureWorks 示例、`requirements-c.txt`。实现严格 JSON/配置校验、授权交集、只读连接、精确名称、主外键整组保序、结构哈希、元数据诊断和 CLI。阶段一配置中的未使用业务字段仅验证并保留，不提前加载模型。

测试：配置/连接失败模拟；SQLite 临时夹具复合键；跨 Schema Inspector 模拟；真实 Chinook 与 sqlite3 独立核对；CLI 子进程与导出。AdventureWorks 未配置则 skip 并记未验证。命令：`.\.venv\Scripts\python.exe -m unittest discover -s eval -p "test_c_stage1*.py" -v`。

## 2 安全 SQL 执行

文件：`validation.py`、`execution.py`、阶段二测试和验收指南。用 SQLGlot 按方言解析单条 SELECT/CTE/集合查询，拒绝写入/SELECT INTO/外部对象/危险函数，按作用域区分 CTE、别名和物理表并验证授权列；不支持的结构保守拒绝。绑定命名标量参数；受控只读事务、数据库超时、输出截断、Decimal/日期序列化、唯一列名。新 Python 执行入口返回 v0.3 字段；旧入口不改。SQLite authorizer 为第二道检查；PostgreSQL 还需真实只读账号验证，不将 AST 称为沙箱。

测试：攻击、CTE/子查询作用域、跨 Schema、参数、超时后恢复、截断边界、序列化、拒绝时库哈希不变；真实 PostgreSQL 独立标记。

## 3 基础自然语言查数

文件：`catalog.py`、`generation.py`、`service.py`、Chinook 最小演示口径、阶段三测试。实现可注入 JSON 模型接口和可选环境变量配置的 OpenAI 兼容 HTTP 适配（不绑定模型厂商）；严格解析 sql/params，无凭据时明确不可用。演示口径不冒充 A 已确认业务标准。C 内部新增 `answer_sql` 草案对象，B 仍负责最终答复；正式接口不改。

测试：注入模拟模型、简单查数、非法 JSON/参数、实际 SQLite 结果；真实模型缺配置记未验证。

## 4 Schema Linking 与复杂查询

文件：`linking.py`、阶段四测试。基于真实 Schema + profile 字典/指标/别名的文本召回、字段命中、外键图路径补全和复合关联；不引入向量库。输出候选、命中原因和未解析槽位，不宣称精确率已评测。复杂查询以可手工核对的订单头/明细夹具测试重复计数、CTE、子查询；模型效果需真实评测。

## 5 澄清、修复与查询证据

文件：扩展 `service.py`、`generation.py` 与阶段五测试。必要槽位/指标/实体歧义先澄清，空结果仍 answered；最多两次修复和共享截止时间，权限/连接问题不交模型绕过；每个候选完整校验。记录最终 SQL、绑定参数、Schema 版本、指标和选择关系、工具事件，不返回隐性思维链。

测试：澄清不执行、实体歧义、修复成功/耗尽/预算、空结果、失败状态映射与可核对证据。语义等价无法普遍自动证明，修复成功不能替代业务结果正确性评测。

## 6 与 B 联调及整体验收

文件：`integration.py`、契约边界测试、PowerShell 总体验收指南和阶段报告。以 v0.3 校验 SQL 工具响应；C 草案到 B 的映射提供调用示例，不新增/重写 B 服务。仅在已有 B 环境可用时实际调用；当前缺 B 实现则交接口测试和联调说明，标真实页面未验证。
