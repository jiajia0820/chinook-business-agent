## 2 列出 profile 与检查连接

```powershell
.\.venv\Scripts\python.exe -m backend.sql_module profiles
.\.venv\Scripts\python.exe -m backend.sql_module check chinook
$LASTEXITCODE
```

预期：profile 列表包含 chinook；连接检查 status=success，table_count=11，database.dialect=sqlite，包含实际 SQLite 版本；退出码 0。不返回连接串、凭据或本机路径。

```powershell
.\.venv\Scripts\python.exe -m backend.sql_module check unknown
$LASTEXITCODE
```

预期：stderr JSON 中 error.code=PROFILE_NOT_FOUND，退出码 1；不会回退到 Chinook。

## 3 查看表、结构与外键

```powershell
.\.venv\Scripts\python.exe -m backend.sql_module tables chinook
.\.venv\Scripts\python.exe -m backend.sql_module table chinook main.PlaylistTrack
.\.venv\Scripts\python.exe -m backend.sql_module table chinook main.InvoiceLine
.\.venv\Scripts\python.exe -m backend.sql_module foreign-keys chinook
```

预期：11 个 main.table 标识；PlaylistTrack 主键依次 PlaylistId、TrackId；每列有 name/data_type/nullable/description；InvoiceLine 有 InvoiceId → main.Invoice.InvoiceId 的外键。每个约束保存 from_columns/to_columns 两组有序列表。SQLite 无表注释时 description=null，limitations 明确说明。

## 4 导出 Schema

```powershell
.\.venv\Scripts\python.exe -m backend.sql_module export-schema chinook --output .\tmp\chinook-schema.json
$schema = Get-Content -LiteralPath .\tmp\chinook-schema.json -Raw -Encoding UTF8 | ConvertFrom-Json
$schema.profile_id
$schema.tables.Count
$schema.schema_version
```

预期：chinook、11、64 位结构哈希；导出 UTF-8 JSON。失败不会覆盖已有导出。此快照不包含记录数或业务数据采样；不要使用 PowerShell 默认重定向替代 --output。

## 6 AdventureWorks：由部署者补齐后再验收

`profiles/examples/adventureworks.profile.json` 为未激活示例。先核对已部署 PostgreSQL 实例中的真实 Schema/表及大小写，不能把示例小写名字当作已验证结构。配置只读账号连接环境变量 ADVENTUREWORKS_DATABASE_URL；通过本地秘密管理或 PowerShell 安全输入注入，不在聊天、源码、日志中粘贴秘密。

创建本地验收配置目录（tmp 已被 Git 忽略）：

```powershell
New-Item -ItemType Directory -Force -Path .\tmp\profiles\adventureworks | Out-Null
Copy-Item -LiteralPath .\profiles\examples\adventureworks.profile.json -Destination .\tmp\profiles\adventureworks\profile.json
# 在 VS Code 编辑该 JSON，将 allowed_schemas/allowed_tables 改成部署实例的准确授权名称。
# 连接环境变量须由部署者在本地安全配置；本指南不提供含密码的命令。
.\.venv\Scripts\python.exe -m backend.sql_module --profiles-dir .\tmp\profiles profiles
.\.venv\Scripts\python.exe -m backend.sql_module --profiles-dir .\tmp\profiles check adventureworks
.\.venv\Scripts\python.exe -m backend.sql_module --profiles-dir .\tmp\profiles tables adventureworks
.\.venv\Scripts\python.exe -m backend.sql_module --profiles-dir .\tmp\profiles foreign-keys adventureworks
.\.venv\Scripts\python.exe -m backend.sql_module --profiles-dir .\tmp\profiles export-schema adventureworks --output .\tmp\adventureworks-schema.json
$env:C_ADVENTUREWORKS_PROFILES_DIR = (Resolve-Path -LiteralPath .\tmp\profiles).Path
.\.venv\Scripts\python.exe -m unittest discover -s eval -p 'test_c_stage1*.py' -v
```

预期：缺连接变量时 PROFILE_UNAVAILABLE/CONFIG_MISSING；连接配置不匹配时明确失败。配置齐全才期望 check 成功并显示实际服务器版本。已配置但连接失败会计为失败，不跳过。真实集成测试当前仅验证连接、授权表结构可读取；复合关系、跨 Schema 同名表等必须按真实导出人工核对，不能用模拟测试代替。

可通过 `table adventureworks schema.table` 查看部署实例中的具体结构。不要为了测试而建表、改库或部署新的业务数据库。
