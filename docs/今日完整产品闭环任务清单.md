# Chinook 完整产品闭环实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 今天跑通 Chinook 结构化查询 + D01-D12 非结构化检索 + 中国大模型 API + 网页展示的完整闭环，并保留答案、SQL、文档证据和计算记录。

**Architecture:** 保持现有 `POST /api/v1/ask` 契约。B 负责请求解析、路由、RAG 和响应组装，C 负责 Schema、NL2SQL、只读 SQL 和结构化结果，A 负责指标口径、文档清单、别名和验收题。真实大模型先接入 C 的 NL2SQL 链路；回答组装先沿用结构化响应 Composer，避免今天同时引入第二套 Agent 主循环。

**Tech Stack:** Python 3.12、FastAPI、Pydantic、LangGraph、SQLite、Vue 3、Vite、OpenAI-compatible Chat Completions API。

## 一、当前基线和已确认问题

当前本地 `main` 与 `origin/main` 都在提交 `3ab8e86`，没有 Git 分支冲突。当前本地只有一个未跟踪的个人架构文件：

```text
docs/b-agent-architecture-plan.md
```

该文件保留，不参与今天的功能提交。

代码当前实际状态：

1. 网页、FastAPI、SQL 工具、D12 检索和证据面板已经存在。
2. B 启动链路使用 `DemoJSONModel`，真实模型 API 没有被调用。
3. C 的 HTTP 模型适配器已经存在，但尚未接入 B 的实际启动路径。
4. profile 的正式指标目前只有 `customer_count`，不能覆盖完整 Chinook 问数。
5. 解析器在 offline 模式主要依赖固定问题别名，不能支撑自由自然语言转 SQL。
6. RAG 运行时只加载 D12，manifest 也限制为单文档。
7. D01-D11 虽然已经在 `data/knowledge/`，但没有进入运行时索引。
8. 计算器和证据绑定当前被 `UnavailableEvidenceResolver` 禁用，目标达成和增长率不能形成正式结论。
9. 本地 D12 文本内容与远程版本逐行一致，但本地是 CRLF，远程是 LF；后端用 SHA-256 和文件大小锁定远程快照，本地直接启动会返回 `PROFILE_UNAVAILABLE`。

## 十一、明确的风险判断

1. 今天只把 D12 换成 12 文档索引而不改 manifest/loader，会继续触发校验失败。

5. 今天先完成 Chinook 完整闭环；AdventureWorks 和 OHR-Bench 不进入今天的验收阻塞。
