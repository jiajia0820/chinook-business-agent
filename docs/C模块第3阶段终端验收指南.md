## 4 真实模型配置（当前未验证）

远程适配接受单次 chat-completions JSON 请求；使用服务端环境变量，不自动读取 .env：

| 环境变量 | 用途 |
|---|---|
| C_SQL_MODEL_ENDPOINT | 已有模型服务的完整 HTTPS chat-completions URL，包含具体请求路径；无凭据/查询参数 |
| C_SQL_MODEL_NAME | 现有服务允许的模型 ID |
| C_SQL_MODEL_API_KEY | 本地秘密管理注入的 API Key |
| C_RUN_REAL_SQL_MODEL | 仅当用户希望运行真实模型集成测试时设为1 |

供应商需支持 messages、response_format=json_object、max_tokens 和 choices[0].message.content 协议；HTTP适配模拟通过不代表任意供应商兼容。供应商不支持这些字段时明确失败，需要适配其协议，不能自动降级执行任意文本。profile.model_profile 暂保留配置，当前 HTTP 模型选择来自以上全局服务端环境变量。

不要在聊天、源码、日志中放 Key，不需下载模型、不新购账号或额度。凭据通过已有本地秘密管理或本地安全输入注入。未配置时运行：

```powershell
.\.venv\Scripts\python.exe -m backend.sql_module ask chinook '客户数量是多少？'
$LASTEXITCODE
```

预期：若没有上述环境变量，则 status=error、PROFILE_UNAVAILABLE、reason=CONFIG_MISSING、退出码1；明确缺模型，不冒充已答复。若已配置，则会实际调用模型，行为和费用由该已有服务决定；本轮未执行此真实调用。

配置现有模型服务后，可用同一条 ask 命令或请求文件去掉 --demo-model 验证。要显式启用真实测试：

```powershell

.\.venv\Scripts\python.exe -m unittest eval.test_c_stage3.ModelHTTPTests.test_real_model -v
```

预期：仅当真实模型配置/服务兼容且生成正确结果才通过；启用后缺配置或服务失败会算失败，不跳过。单题成功只代表该题，不代表自然语言正确率评测完成。

## 5 Python 能力入口

```python
from backend.sql_module import Registry, AccessContext
from backend.sql_module.service import NLQueryService
from backend.sql_module.generation import DemoJSONModel
r = Registry.load()
service = NLQueryService(r, DemoJSONModel())  # 真实配置时省略第二参数
result = service.answer_sql({
    "request_id":"manual-001", "profile_id":"chinook",
    "question":"客户数量是多少？",
    "context":{"metric_ids":["customer_count"]},
    "options":{"show_trace":False,"max_rows":50}
}, AccessContext.local(r))
```

真实服务端应由认证配置构造 AccessContext；local 是本地验收工具的管理范围，不接受前端自报角色。自定义模型对象仅需实现 generate_json(messages, output_schema, deadline)，返回 sql/params JSON 字符串；不执行模型文本中的代码。
