# Chinook Business Agent UI 重设计 spec

日期：2026-10-14  
状态：待用户审阅  
范围：`services/web` 现有页面展示层

## 背景

当前网页是单列的浅色问答页面，提问区、回答区、会话记录和证据区纵向堆叠。产品实际定位是可解释的数据分析智能体：用户需要同时理解问题、Agent 的运行状态、结论、SQL / 文档来源、指标口径和后端工具步骤。桌面端运营人员会长时间使用，因此页面需要更强的任务状态感和更稳定的三栏信息层级。

本次采用 **C1 · 常驻证据舱**：左侧会话导航、中间回答画布、右侧常驻证据区。视觉基调为深色任务舱，蓝色表示当前交互，绿色表示成功，琥珀色表示需要关注，红色表示错误。

## 范围与约束

本轮只修改 `services/web` 的 UI 展示层和前端本地展示状态：

- 不修改后端代码、API 路由、接口契约、请求字段、响应字段、Agent 路由和数据处理逻辑。
- 不新增模型能力、数据库能力、RAG 能力、图表数据接口或业务指标。
- 保留现有提问、示例问题、澄清、重试、停止等待、新会话、会话历史和证据引用行为。
- 概念图中的趋势图只用于表达视觉节奏；本轮不引入新的图表解析或数据生成逻辑。
- 保留现有 `data-testid` 和可访问语义，必要时只移动节点位置或补充展示容器。

## 页面结构

### 1. 应用外壳

页面使用深色背景和三栏网格：

- 左栏约 220px：产品标识、当前工作区入口、新会话、会话历史和 profile 信息。
- 中栏自适应：问题、运行状态、回答、现有 SQL 表格 / 文档摘要 / 计算结果和追问输入。
- 右栏约 340–380px：常驻 Evidence dock，展示 SQL、Sources、Metrics、Trace 四类已有证据。

左栏和右栏使用固定的深色面板，中栏保持最大的阅读宽度。面板采用 1px 边框、轻微阴影和小圆角，不使用玻璃模糊或大面积渐变。

### 2. 左栏会话区

左栏只重组已有页面能力：

- “新会话”继续调用现有 `newSession`。
- 会话历史继续使用 `history`，点击问题仍然只是回填输入框。
- profile 继续显示现有 `PROFILE_ID`，不新增 profile 切换逻辑。
- 不加入未实现的导航页面、账户系统、团队协作或设置功能。

### 3. 中央任务画布

中央区域的默认阅读顺序为：

1. 当前问题和本轮请求信息；
2. loading / answered / clarification / unsupported / error 等现有状态；
3. 回答结论和已有引用链接；
4. 现有 SQL 结果、文档片段、计算结果的摘要或表格；
5. 追问输入和操作按钮。

`AskResult.vue` 继续负责状态标题、回答、引用跳转、澄清、错误和重试。视觉上把结论放在更醒目的任务卡中，把请求 ID、业务路由等元数据降为辅助信息。

### 4. 右侧 Evidence dock

右栏默认展开，使用本地 UI 状态记录当前选中的证据分组；不改变响应数据。四个分组对应现有组件：

- **SQL**：`SqlEvidence.vue` 的查询状态、SQL 文本和结果表格；
- **Sources**：`DocumentEvidence.vue` 的文档标题、位置和原文片段；
- **Metrics**：`MetricDefinitions.vue` 的指标定义和来源引用；
- **Trace**：`TraceEvidence.vue` 的后端工具步骤。

Trace 继续明确标注为后端工具步骤，不展示模型隐性思维链。引用点击后，右栏对应卡片展开、滚动并高亮，保留现有 `focusEvidence` 行为。

### 5. 输入与运行状态

问题输入仍由现有 `useAskWorkspace` 驱动。发送、停止等待、取消当前问题、手动重试和 Ctrl+Enter 行为不变。loading 状态使用明确的运行状态条和步骤视觉；步骤内容只来自现有 `trace`，不虚构运行过程。

## 视觉系统

- 页面背景：`#0B1220`；主面板：`#111B2D`；次级面板：`#17243A`；边框：`#263A59`。
- 主文字：`#E8EFFC`；次文字：`#8EA2C4`；主交互：`#6E9CFF`。
- 成功：`#7AE2B0`；关注：`#EFBD72`；错误：`#F18C8C`。
- 使用高可读无衬线字体，代码和 SQL 使用等宽字体。
- 所有交互控件保留清晰 hover、focus-visible、disabled 状态；动画控制在短时过渡，并遵守 `prefers-reduced-motion`。
- 不使用 emoji 作为图标；若需要图标，使用现有文本 / CSS 形状或项目已有资源，不引入新的图标体系依赖。

## 响应式行为

- 宽桌面：完整三栏布局。
- 中等宽度：右侧 Evidence dock 可折叠为抽屉，中栏保持优先可读宽度。
- 窄屏：左栏折叠为入口，Evidence dock 变为底部或侧边抽屉；所有现有操作仍可访问。
- 不新增移动端业务流程，不改变请求和响应行为。

## 验收标准

- 页面呈现 C1 深色任务舱的三栏信息层级，回答和证据可以同时查看。
- 现有提问、澄清、重试、停止等待、新会话、会话历史、引用跳转和证据展开行为继续可用。
- 现有 API 请求和响应结构不变，后端与接口契约文件无修改。
- SQL、文档、指标、计算、Trace 只展示响应中已有数据，不补造业务内容。
- 保留现有测试选择器和可访问标签；键盘焦点和深色背景下的文字对比度可用。
- `services/web` 的 `npm run verify` 通过。

## 不在本轮范围内

- 后端或 Agent 逻辑改造；
- API / OpenAPI / 契约字段变更；
- 新增图表、导出、收藏、权限、登录、协作和多 profile 管理；
- 新增第三方 UI 框架、图标库或数据可视化依赖；
- 重新设计产品文案或改变业务状态语义。
